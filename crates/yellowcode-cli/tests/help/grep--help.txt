Поиск в текстах модулей, запросах схем компоновки данных и именах объектов, как grep

Usage: yellowcode grep [OPTIONS] <PATTERN> <SOURCE>

Arguments:
  <PATTERN>  Регулярное выражение без учёта регистра; с -F — подстрока (`ё` равна `е`). Если шаблон начинается с `-`, поставьте перед ним `--`
  <SOURCE>   Конфигурация: CF, DT, файл 1Cv8.1CD или каталог базы

Options:
      --memory-limit <MEMORY_LIMIT>  Бюджет памяти на чтение конфигурации из DT; память самой модели расходуется сверх него
      --platform-build <BUILD>       Точная версия эмулируемой платформы (не режим совместимости конфигурации) [default: 8.5.1.1529]
      --kind <KIND>                  Только объекты этих видов через запятую или повтором флага, например Справочник,Документ
      --path <PATH>                  Объект и всё под ним, например Справочник.Номенклатура; флаг можно повторять
      --subsystem <SUBSYSTEM>        Только объекты подсистемы, полный (Подсистема.А.Подсистема.Б) или краткий (А.Б) путь; флаг можно повторять
      --in <МЕСТА>                   Где искать, через запятую: code — тексты модулей, queries — тексты запросов схем компоновки данных, names — имена и синонимы объектов [default: code] [possible values: code, queries, names]
  -F, --fixed-strings                Шаблон — подстрока, а не регулярное выражение
  -s, --case-sensitive               Различать регистр в текстах модулей и запросов; на `--in names` не влияет, имена 1С регистронезависимы
  -C, --context <N>                  Строк контекста вокруг совпадения в текстах модулей и запросов [default: 0]
  -l, --files-with-matches           Печатать только пути с совпадениями
  -c, --count                        Печатать для каждого пути число совпадений
      --max-count <N>                Сколько строк-совпадений выдать, не меньше 1 (строки контекста не считаются) [default: 1000]
      --format <FORMAT>              Формат вывода [default: text] [possible values: json, text]
  -h, --help                         Print help

Вывод: `путь:строка:текст` для совпадения и `путь-строка-текст` для строки контекста; совпадение в имени объекта печатается как `путь:имя`. Путь и строку читает `module show --lines`. У запроса схемы компоновки данных путь — `ПУТЬ_МАКЕТА#НАБОР`, строки считаются с 1 от начала запроса (`template show --set НАБОР --query`); схема больше предела просмотра пропускается, stderr сообщает об этом. Код возврата: 0 — есть совпадения, 1 — нет, 2 — ошибка (аргументы, источник, выражение, путь области). Результат длиннее `--max-count` обрезается; об этом сообщает stderr, код остаётся 0.

Примеры:
  # Где вызывается процедура (регулярное выражение, без учёта регистра)
  yellowcode grep 'ПользователиСлужебный\.ПроверитьПрава' configuration.cf

  # Подстрока в модулях документов, по 2 строки контекста
  yellowcode grep -F 'НачатьТранзакцию' configuration.cf --kind Документ -C 2

  # Обработчики ПередЗаписью в подсистеме
  yellowcode grep 'Процедура\s+ПередЗаписью' configuration.cf --subsystem СтандартныеПодсистемы.Пользователи

  # Только пути модулей с совпадениями
  yellowcode grep -l 'ЗаписьЖурналаРегистрации' configuration.cf

  # Объекты, в имени или синониме которых есть «Контрагент»
  yellowcode grep -F Контрагент configuration.cf --in names

  # Где в запросах схем компоновки данных упомянут регистр
  yellowcode grep -F РегистрНакопления.Продажи configuration.cf --in queries

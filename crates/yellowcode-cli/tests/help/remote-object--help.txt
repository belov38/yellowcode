Прочитать объект по ссылке так, как его получает форма объекта: реквизиты и табличные части

Usage: yellowcode remote object [OPTIONS] --ref <ССЫЛКА> <URL>

Arguments:
  <URL>  Адрес сервера 1С: веб-публикация или ibsrv --http-port (http://, https://), либо прямое подключение /S — Srvr="хост[:порт]";Ref="база"; или tcp://хост[:порт]/база

Options:
      --platform-build <BUILD>   Точная версия эмулируемой платформы (не режим совместимости конфигурации) [default: 8.5.1.1529]
      --user <ПОЛЬЗОВАТЕЛЬ>      Имя пользователя информационной базы для входа с паролем; пароль берётся из --password-env или строкой из stdin (не с терминала)
      --password-env <ИМЯ>       Взять пароль из этой переменной окружения
      --progress <MODE>          Ход работы в stderr: auto — строка на терминале, always — строки для журнала, never — без него (по умолчанию переменная YELLOWCODE_PROGRESS, иначе auto) [possible values: auto, always, never]
      --strong-password          Пользователь со стойким паролем: пароль передаётся как набран (по умолчанию — как у прежних версий, в верхнем регистре)
      --ca-cert <PATH>           Доверять также сертификатам из этого файла PEM: корпоративный центр сертификации или самоподписанный сертификат сервера; можно повторять. Добавляются к встроенным корням, только для https://
      --server-version <ВЕРСИЯ>  Версия платформы, которую клиент сообщает серверу (например 8.3.27.2214); без неё — 8.5.1.1529, а вход, отклонённый из-за версии, повторяется один раз с версией сервера из ответа
      --worker <ХОСТ:ПОРТ>       Только /S: подключаться к рабочему процессу по этому адресу, а не по имени, которое назвал менеджер
      --ref <ССЫЛКА>             Ссылка на объект: cfg:<Вид>Ref.<Имя>(<uuid>), как её выводит yellowcode remote call, или <Вид>.<Имя>(<uuid>) с русским названием вида, например Документ.Счет(<uuid>). Виды: Справочник, Документ, ПланВидовХарактеристик, ПланСчетов, ПланВидовРасчета, ПланОбмена, БизнесПроцесс, Задача; на сервере проверены справочники и документы
      --json                     Вывести один объект JSON: реквизиты и строки табличных частей в типизированном JSON --param-json; значение типа, который клиент не разбирает, — {"raw": текст}. Представления ссылок — отдельный ключ presentations
      --no-presentations         Не запрашивать представления ссылок и значений перечислений объекта. По умолчанию они запрашиваются после закрытия формы, как в yellowcode remote call
  -h, --help                     Print help

Войти на сервер, открыть форму объекта по ссылке, прочитать реквизиты и табличные части и закрыть форму, как это делает тонкий клиент (logForm?cmd=query, dataDescrWMethods, processFormsClose). Открытие формы выполняет код формы и объекта на сервере, как у пользователя; запись не выполняется, объект не блокируется

Пароль пользователя (--user) не передаётся в командной строке и не набирается с клавиатуры: --password-env ИМЯ берёт его из переменной окружения, а без этого флага пароль читается одной строкой из stdin, поданного конвейером или из файла. Если stdin — терминал, команда отказывает до первого запроса. Пустой пароль — пустая строка: `printf '\n' | yellowcode remote …` в sh, bash, zsh; `echo.| yellowcode remote …` в cmd. Ввод, который кончился раньше первой строки, — ошибка.

Адрес вида Srvr="хост[:порт]";Ref="база"; (строка подключения 1С) или tcp://хост[:порт]/база — подключение к серверу напрямую, как у тонкого клиента по /S, без веб-публикации: к менеджеру кластера (порт по умолчанию 1541) или к ibsrv --direct-regport. Менеджер называет рабочий процесс по имени компьютера сервера; если это имя отсюда не разрешается, адрес рабочего процесса задаёт --worker хост:порт. Несколько менеджеров через запятую (Srvr="хост1:порт1,хост2:порт2") перебираются, как у тонкого клиента: по порядку текстов хост:порт, до трёх кругов; недоступный или отказавший менеджер передаёт поиск базы следующему. Поддерживается только уровень безопасности соединения 0 (сервер, требующий шифрованного канала, получает отказ с объяснением). Если сервер завершил сеанс (перезапуск, rac session terminate), команда входит заново и повторяет запрос, если он только читает; вызов серверной процедуры, вызов формы и запись не повторяются.

Адрес https:// — соединение по TLS. Сертификат сервера проверяется всегда: по встроенным корням Mozilla (webpki-roots) и по сертификатам из файлов --ca-cert; отключить проверку нельзя.

Примеры:
  # Сводка сервера при входе без пользователя
  yellowcode remote info http://127.0.0.1:28736

  # Параметры входа базы с пользователями, без входа и без пароля
  yellowcode remote info http://server/base --auth-settings-only

  # Метаданные под пользователем, пароль из переменной окружения YC_PASSWORD
  yellowcode remote metadata http://server/base --user Администратор --password-env YC_PASSWORD

  # Напрямую к кластеру (/S), без веб-публикации
  yellowcode remote info 'Srvr="server:1541";Ref="base";' --user Администратор --password-env YC_PASSWORD

  # Напрямую к ibsrv --direct-regport через туннель: рабочий процесс тоже через туннель
  yellowcode remote info tcp://127.0.0.1:28730/base --worker 127.0.0.1:28731

  # Веб-публикация по HTTPS с корпоративным центром сертификации
  yellowcode remote info https://server/base --ca-cert corp-ca.pem

  # Пароль из файла
  yellowcode remote info http://server/base --user Администратор < password.txt

  # Пользователь без пароля (в cmd: echo.| yellowcode remote info …)
  printf '\n' | yellowcode remote info http://server/base --user Гость

  # Вызвать экспортную функцию общего модуля с параметрами
  yellowcode remote call http://server/base --call МойМодуль.МояФункция --param n:10 --param s:текст

  # Записать тексты клиентских модулей в каталог
  yellowcode remote modules http://server/base --out client-modules

  # Вторая страница списка документов, по убыванию даты
  yellowcode remote list http://server/base --object Документ.ПриходнаяНакладная --order 'Дата desc' --page 2

  # Реквизиты формы отчёта, затем отчёт: серверная процедура формы с параметрами и её табличный документ
  yellowcode remote report http://server/base --form Отчет.Остатки.Форма.ФормаОтчета
  yellowcode remote report http://server/base --form Отчет.Остатки.Форма.ФормаОтчета --call СформироватьНаСервере --param d:2026-11-30T23:59:59 --format csv > report.csv

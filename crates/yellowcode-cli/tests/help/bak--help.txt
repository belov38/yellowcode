Исследовать резервную копию MS SQL Server (экспериментально)

Usage: yellowcode bak [OPTIONS] <COMMAND>

Commands:
  inspect  Проверить структуру резервной копии без её восстановления
  convert  Восстановить копию через MS SQL Server и сохранить CF, DT или 1CD
  help     Print this message or the help of the given subcommand(s)

Options:
      --platform-build <BUILD>  Точная версия эмулируемой платформы (не режим совместимости конфигурации) [default: 8.5.1.1529]
  -h, --help                    Print help

Экспериментально. CF: основная конфигурация из полной копии одним файлом через MS SQL Server, сжатые копии допускаются. Проверено на учебной базе (побайтно с выгрузкой Конфигуратора). Если конфигурацию базы обновляли динамически, CF содержит применённый вид, как выгрузка Конфигуратора; флаг --raw возвращает CONFIG как он хранится в базе. Восстановление проверено только на SQL Server 2022: в Docker для Linux и одним реальным запуском на сервере для Windows (результат побайтно совпал с результатом на Linux); другие версии сервера не проверялись. DT и 1CD: только небольшие учебные базы без пользователей, типовые конфигурации отклоняются. До восстановления отклоняются разностные и журнальные наборы, шифрованные (в том числе TDE) и составные (striped) копии, копии, помеченные повреждёнными, и снимки (отказ для снимков проверен на подставленных заголовках, настоящей копии-снимка не было). Обрезанную копию обнаруживает сам SQL Server во время восстановления: очистка выполняется, её итог выводится.

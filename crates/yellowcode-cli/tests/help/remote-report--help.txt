Открыть форму отчёта и показать её реквизиты; с --call — вызвать серверную процедуру формы (с --poll — дождаться длительной операции), с --generate — сформировать отчёт на СКД; вывести табличный документ

Usage: yellowcode remote report [OPTIONS] <--form <ИМЯ_ФОРМЫ>|--report <ОТЧЕТ>> <URL>

Arguments:
  <URL>  Адрес сервера 1С: веб-публикация или ibsrv --http-port (http://, https://), либо прямое подключение /S — Srvr="хост[:порт]";Ref="база"; или tcp://хост[:порт]/база

Войти на сервер, открыть форму по её имени (logForm?cmd=query) и показать её реквизиты с типами; реквизит-табличный документ помечен (spreadsheet). С --call вызвать серверную процедуру этой формы (&НаСервере, как её зовёт клиентский обработчик команды «Сформировать») с параметрами --param/--param-json и вывести каждый табличный документ, который она изменила: строки документа, тексты ячеек через ` | `. Документ без содержимого дочитывается по строкам (moxel?cmd=getRowContents). Форма закрывается в конце (processFormsClose). Какую процедуру и с какими параметрами зовёт команда формы, видно в тексте модуля формы (remote modules --out, contextModuleId формы).

Клиентский код формы и конфигурации CLI не выполняет; то, что он делает на сервере, задаётся флагами. --init-call — функция общего модуля с вызовом сервера, которую клиентский код зовёт при запуске клиента (до открытия формы). --attr — реквизиты формы, которые клиентский код заполняет при открытии; они уходят с первым вызовом. --before — серверные процедуры формы без параметров, которые клиентский код зовёт при открытии, по порядку. Длительная операция (формирование в фоне): --call её запускает, --poll опрашивает, пока процедура опроса не изменит табличный документ или не скажет, что операция завершилась (--poll-while — поле её Структуры), не дольше --timeout. Если --call вернула Ложь, операция не запущена и опроса нет. После вызовов выводятся строки call: (процедура и что она вернула), state: (текст состояния поля формы — например, ошибка формирования) и message: (сообщения пользователю).

Отчёт на схеме компоновки данных (СКД): --report Отчет.X открывает его форму по умолчанию (Отчет.X.Форма), --form — любую форму отчёта. Показываются варианты отчёта (текущий отмечен *) и пользовательские настройки (параметры и отборы: имя, заголовок, используется ли, значение и его тип). С --generate отчёт формируется платформенной командой «Сформировать» формы (logForm?cmd=call controller::composeResult) с настройками формы и изменениями --set, --filter, --off; сервер этих изменений не сохраняет. Значение приводится к типу параметра или поля схемы: строка как дана, число, булево (да/нет), дата ГГГГ-ММ-ДД[Тчч:мм:сс], стандартный период 'ГГГГ-ММ-ДД..ГГГГ-ММ-ДД' или вариант периода (ThisYear, LastMonth, …), значение перечисления по имени, ссылка — её uuid или представление (поиск как при вводе текста в поле: ни одного или несколько найденных — ошибка до формирования). Неизвестная настройка, неверное значение и составной тип — ошибка до формирования. --details добавляет расшифровку каждой ячейки (dcs?cmd=loadDetailsPart): значения полей ячейки и её группировок. Форма, «Сформировать» которой — код конфигурации (например, форма отчёта БСП), документа не даёт: это ошибка с подсказкой вызвать её серверную процедуру через --call (с --poll, если она формирует отчёт в фоне).

ВНИМАНИЕ: --variant ЗАПИСЫВАЕТ В БАЗУ. Сервер запоминает выбранный вариант как текущий вариант отчёта у пользователя (в хранилище его настроек), так же как при выборе варианта в клиенте 1С: следующее открытие отчёта этим пользователем, в том числе в клиенте 1С, начнётся с этого варианта. Без --variant команда открывает текущий вариант и настроек не меняет.

ВНИМАНИЕ: --call, --before, --poll, --init-call и --generate выполняют код конфигурации на сервере, как remote call: процедуры формы и обработчики отчёта могут записывать данные базы. Вызывайте только процедуры и отчёты, про которые известно, что они только читают.

Пределы: 100000 строк, 10000 колонок и 20000000 клеток (строки × колонки) на документ, 2000000 ячеек с текстом на отчёт; больший отчёт — ошибка без вывода.

Пароль пользователя (--user) не передаётся в командной строке и не набирается с клавиатуры: --password-env ИМЯ берёт его из переменной окружения, а без этого флага пароль читается одной строкой из stdin, поданного конвейером или из файла. Если stdin — терминал, команда отказывает до первого запроса. Пустой пароль — пустая строка: `printf '\n' | yellowcode remote …` в sh, bash, zsh; `echo.| yellowcode remote …` в cmd. Ввод, который кончился раньше первой строки, — ошибка.

Адрес вида Srvr="хост[:порт]";Ref="база"; (строка подключения 1С) или tcp://хост[:порт]/база — подключение к серверу напрямую, как у тонкого клиента по /S, без веб-публикации: к менеджеру кластера (порт по умолчанию 1541) или к ibsrv --direct-regport. Менеджер называет рабочий процесс по имени компьютера сервера; если это имя отсюда не разрешается, адрес рабочего процесса задаёт --worker хост:порт. Поддерживается только уровень безопасности соединения 0 (сервер, требующий шифрованного канала, получает отказ с объяснением).

Адрес https:// — соединение по TLS. Сертификат сервера проверяется всегда: по встроенным корням Mozilla (webpki-roots) и по сертификатам из файлов --ca-cert; отключить проверку нельзя.

Примеры:
  # Сводка сервера при входе без пользователя
  yellowcode remote info http://127.0.0.1:28736

  # Параметры входа базы с пользователями, без входа и без пароля
  yellowcode remote info http://server/base --auth-settings-only

  # Метаданные под пользователем, пароль из переменной окружения YC_PASSWORD
  yellowcode remote metadata http://server/base --user Администратор --password-env YC_PASSWORD

  # Напрямую к кластеру (/S), без веб-публикации
  yellowcode remote info 'Srvr="server:1541";Ref="base";' --user Администратор --password-env YC_PASSWORD

  # Напрямую к ibsrv --direct-regport через туннель: рабочий процесс тоже через туннель
  yellowcode remote info tcp://127.0.0.1:28730/base --worker 127.0.0.1:28731

  # Веб-публикация по HTTPS с корпоративным центром сертификации
  yellowcode remote info https://server/base --ca-cert corp-ca.pem

  # Пароль из файла
  yellowcode remote info http://server/base --user Администратор < password.txt

  # Пользователь без пароля (в cmd: echo.| yellowcode remote info …)
  printf '\n' | yellowcode remote info http://server/base --user Гость

  # Вызвать экспортную функцию общего модуля с параметрами
  yellowcode remote call http://server/base --call МойМодуль.МояФункция --param n:10 --param s:текст

  # Записать тексты клиентских модулей в каталог
  yellowcode remote modules http://server/base --out client-modules

  # Вторая страница списка документов, по убыванию даты
  yellowcode remote list http://server/base --object Документ.ПриходнаяНакладная --order 'Дата desc' --page 2

  # Реквизиты формы отчёта, затем отчёт: серверная процедура формы с параметрами и её табличный документ
  yellowcode remote report http://server/base --form Отчет.Остатки.Форма.ФормаОтчета
  yellowcode remote report http://server/base --form Отчет.Остатки.Форма.ФормаОтчета --call СформироватьНаСервере --param d:2026-11-30T23:59:59 --format csv > report.csv

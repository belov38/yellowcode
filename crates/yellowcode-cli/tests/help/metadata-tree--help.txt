Дерево метаданных, целиком или от одного объекта

Usage: yellowcode metadata tree [OPTIONS] <SOURCE>

Arguments:
  <SOURCE>  Конфигурация: CF, DT, файл 1Cv8.1CD или каталог базы

Options:
      --memory-limit <MEMORY_LIMIT>  Бюджет памяти на чтение конфигурации из DT; память самой модели расходуется сверх него
      --platform-build <BUILD>       Точная версия эмулируемой платформы (не режим совместимости конфигурации) [default: 8.5.1.1529]
      --depth <DEPTH>                Глубина от выбранного корня: 0 — только корень, 1 — с дочерними; без параметра — вся ветка
      --path <PATH>                  Объект, от которого строить дерево, например Справочник.Номенклатура
      --kind <KIND>                  Только объекты этих видов через запятую, например Справочник,Документ
      --flat                         JSON плоским списком узлов (с parentId и depth) вместо вложенного дерева
      --format <FORMAT>              Формат вывода [default: json] [possible values: json, text]
  -h, --help                         Print help

Пути к объектам — русские или английские имена через точку: Справочник.Номенклатура
или Catalog.Номенклатура, реквизит — Справочник.Номенклатура.Реквизит.Артикул.

Примеры:
  # Всё дерево метаданных в JSON
  yellowcode metadata tree configuration.cf > tree.json

  # Справочники и документы, два уровня, текстом
  yellowcode metadata tree configuration.cf --kind Справочник,Документ --depth 2 --format text

  # Один справочник с реквизитами и табличными частями
  yellowcode metadata tree base --path Справочник.Контрагенты --depth 2 --format text

  # Плоский список узлов с parentId и depth
  yellowcode metadata tree backup.dt --flat

  # Свойства реквизита
  yellowcode metadata show configuration.cf Справочник.Контрагенты.Реквизит.ИНН --format text
